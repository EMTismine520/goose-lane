# 鹅巷食光

当前为双页重制版：盘内生产与烹饪、体力、两条新食物链、6道料理、12单和3处建设。旧档保留并迁移。详见 [新版验收](docs/TWO_PAGE_VALIDATION.md) 和 [规则数值](docs/TWO_PAGE_RULES.md)。

> 以下旧版介绍保留作历史参考；免费生成及三页面描述不适用于新版。

合成一点食材，煮一碗热乎，把一条临河老街慢慢变成家。

原创、单人、移动优先的合成烹饪经营游戏。包含六章主线、六家三阶段店铺、八条七阶合成链、24 道料理、84 个订单、12 位居民、24 件装饰和 80 条食材/料理图鉴。生成食材不收费，没有广告或付费体力。

## 怎么玩

1. 两份相同食材可以二合。拖拽、点选来源再点目标都可操作；不同食材会交换位置。
2. 下方补给篮免费生成食材，12 份配额用完后 8 秒补货；满盘不消耗配额。
3. 选择厨具配方，原子消耗食材后开始烹饪；等待时可继续合成，完成后手动领取。
4. 订单整单交付，缺料不扣其他物品；仓库食材也参与计数和消耗。
5. 金币修店，开张后可选择小费或加工效率装饰；完成当天全部订单并让小店开张，再主动迎接下一天。
6. 在图鉴查看来源、整条合成链、配方和居民故事。出售后可撤销一次，后续资产变化会结束撤销资格。

## 保存与恢复

- 每个成功操作先完成 IndexedDB 事务，再更新界面。写入失败不结算，显示错误并允许导出当前进度。
- 保留当前与上一份快照。损坏时尝试恢复有效快照；双档损坏提供原档导出与显式备份导入，不静默重开。
- 设置中可导出/导入 JSON；替换和手动回滚前先下载当前备份。
- 支持 Web Locks 时，一个窗口经营，其他窗口只读；关闭原窗口后可接管。缺少 Web Locks 的浏览器使用 IndexedDB 同一事务中的存档令牌比对：另一窗口保存后，旧窗口的写入被拒绝，必须重新载入最新进度后继续。需要 HTTPS 或 localhost 安全上下文。
- 刷新与后台使用结束时间戳恢复加工。系统时钟倒退采用保存时间下限；异常手动改时可能需要等待追平。
- 本地进度属于当前设备、浏览器和站点地址。更换地址或设备前先导出；浏览器清理数据会清理本地存档。

## 离线与更新

正式构建使用内容哈希生成离线缓存，首次完整联网加载后可离线使用。新版本等待玩家点击更新；未确认前保持旧版资源一致。开发服务器不启用缓存。详见 [PWA 说明](docs/PWA.md)。

## 工程

| 目录 | 内容 |
| --- | --- |
| `src/domain` | 纯 TypeScript 命令、状态、资产与时间规则 |
| `src/content` | 食材、配方、订单、店铺、居民及装饰配置 |
| `src/game` | Phaser 棋盘、输入、动效及街区居民表现 |
| `src/ui` | React 订单、厨具、街区、图鉴、仓库与设置 |
| `src/persistence` | IndexedDB、校验、迁移、损坏恢复与备份 |
| `src/platform` | 串行提交控制、写锁、Web Audio、PWA |
| `src/diagnostics` | 四策略全流程经济模拟及机器可读结果 |
| `tests` | 规则、随机不变量、存档、并发、音频与缓存测试 |
| `public/assets` | 实际使用的 WebP 街景与透明食物图集 |
| `art-source` | 原始生成 PNG，保留供后续资产制作 |

使用锁定版本 Phaser 4.2.1、React 19.2.0、TypeScript 5.9.3、Vite 7.1.12。界面通过领域命令修改状态，画面与音效不决定资产数量。项目从空目录自建；没有复制调研中其他餐厅游戏的代码或素材。

本轮 83 项自动测试通过，生产构建通过。四策略全部完成六章、所有建设与装饰、完整 80 条图鉴，最终余额均为 904 金币。完整记录与限制见 [交付验收](docs/DELIVERY.md)、[规则和经济](docs/GAME_RULES.md)、[模拟结果说明](docs/VALIDATION_DOMAIN.md)。

真实 iOS/Android 设备、5 名陌生玩家上手率、持续 30 分钟内存/热性能和目标 3–5 小时真人体验尚未验证，不能把自动模拟当成这些指标达标。

原创图像由内置 imagegen 制作，提示词、原始文件与压缩过程见 [素材清单](docs/ASSETS.md)。原创音频通过 Web Audio 合成；字符和店铺使用项目内 SVG/CSS，字体使用系统字体，不依赖外部字体 CDN。第三方软件许可及原文见 [第三方声明](docs/THIRD_PARTY_NOTICES.md)，构建时一并复制进 `dist/notices/`。

微信内置浏览器和夸克浏览器使用 Canvas 绘制棋盘，并直接用图片网址加载素材，避免 XHR 转 Blob 后等待图片解码；其他浏览器保留 Phaser 自动选择的绘制方式。棋盘尺寸以外层布局为准，并在场景资源加载完成后重新测量。加载界面显示引擎或素材进度，30 秒没有进展时提供重新加载入口，保留已保存的进度。
