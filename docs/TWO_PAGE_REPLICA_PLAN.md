# 《肥鹅美食街》双页面复刻计划

日期：2026-10-24（北京时间） · 状态：实玩调研与代码审查完成，等待按本计划实施。

本轮目标：复刻原作的页面结构、操作路径、信息密度与反馈节奏。主页面严格限定为「美食合成」和「美食街」，通过左下角同位置按钮互相切换。约 75% 的制作与验收精力投入合成页。先交付一段完整、精致、可持续操作的体验，再扩内容。

本计划取代根目录旧计划中“三导航、宽屏经营面板、优先扩六章内容”的实施方向。旧计划与旧版本保留作为历史记录。当前名称暂沿用项目名称；正式素材按同一风格重制，原作截图用作视觉与行为参考。

平台为用户已打开的抖音桌面小游戏，画面标记 Version 1.9.1，已有进度第 6 天。后半程由用户实际操作，助手逐步观察截图；不是从零开始的新手流程。以下数字是本次场景观测，不能外推成完整概率、经济或所有等级的通用参数。

| 操作 | 可核验结果 | 对复刻的约束 |

| 美食合成页 | 美食街页 |
| --- | --- |
| 顶部：经营日、体力、金币等实际资源 | 顶部：沿用相同资源条 |
| 上部：紧凑顾客订单带，卡片可横向浏览 | 主体：等距当前店铺、箱子、货架、柜台、角色 |

合成场景在切页时暂停输入与表现，不销毁；时间类任务继续按时间戳推进。保存选中物 UID、订单带位置和教学节点。返回时仍能找到原来的物品。弹层开启时屏蔽背后棋盘输入，关闭按钮始终可用。

**4. 合成页精确布局方案**

主设计画布为 390×780 CSS px（应用可用区，不包含浏览器/系统栏）。参考原作的竖屏构图，桌面保持同一竖屏游戏容器，最大宽度约 430px；外侧延展背景，不改成管理后台双栏。

建议初始布局预算：顶部资源 52px；顾客与背景区 132px；棋盘内容 350×450px、外框 358×458px；底部物品栏 78px；其他间距合计 60px，总高正好 780px。格子为 50px。系统安全区在计算应用可用区时先扣除，不再重复计入间距。

棋盘采用 **7 列、9 行的可视网格**：本次参考画面上部 6 行常规格，下部约 3 行等高纸箱/合并锁区。7×9 是按截图几何制定的实现方案；下部究竟如何映射内部可用格、跨格奖励块、解锁条件，尚未通过解锁操作验证。使用布局配置描述 footprint 和锁区，不把原作内部逻辑臆测成固定数组规则。

尺寸计算：`cell = floor(min((可用宽度 - 左右外边距 - 棋盘横向边框及内边距 - 6×列间距) / 7, (可用高度 - 顶栏 - 订单带 - 底栏 - 区块间距 - 棋盘纵向边框及内边距 - 8×行间距) / 9))`。所有尺寸基于扣除浏览器栏与系统安全区后的应用可用区。

短屏必须采用独立预算：360×640 可用区中，顶栏 48px、订单带 88px、棋盘外框 306×390px（内容294×378px、单格42px、横纵边框及内边距各合计12px）、底栏74px、其他间距40px，合计640px。棋盘居中，不能照搬780px布局再缩小。可用高度降至606px时，改为44px顶栏、80px订单带、390px棋盘、70px底栏及22px间距，仍保留42px单格。高度不足606px进入紧凑单订单布局并重新验收，不承诺沿用同一单格尺寸。常规较高屏幕目标单格44–50px；不要用缩小文字解决布局溢出。

| 区域 | 具体要求 | 完成标准 |
| --- | --- | --- |
| 资源条 | 图标+数值，体力变化与金币入账可定位；仅展示已经实现的货币 | 数字清楚，不存在点击无响应的装饰性加号 |
| 顾客带 | 鹅头像、所需食物、已有/需求、奖励紧密成组；缺件与可交付状态有符号差异 | 同时看清约 2 张主卡，更多订单在带内横滑 |
| 棋盘 | 温暖浅色格底、适量边框；食物在视觉上比格子突出 | 完整外边界与底部锁区同屏，页面本身不滚动 |
| 锁区 | 箱子、遮蔽厨具、待解锁食材区别表现；解锁日/条件来自数据 | 标签与可操作性一致，不用假数字装饰 |
| 底部信息 | 空闲、选中食材、生产器、投料、加工中、待取等状态切换 | 高度稳定，不使棋盘随选择上下跳动 |
| 左下切换 | 约 56×56px，8–12px 安全边距，两页保持同一锚点 | 不与删除、底部系统手势或棋盘格重叠 |

默认只强调一个下一步行动：教学目标、可交订单或当前厨具。不能所有按钮同时跳动。首屏去掉英文装饰标语、宣传大标题、长说明、页脚和网页式白卡堆叠。

**5. 盘内操作规格**

以下未被本轮验证的边界行为是本项目设计决定，实施时在行为表中标记，不冒称原作规则。

| 操作 | 规则与反馈 |
| --- | --- |
| 点击生产器 | 校验解锁、体力和空格；成功一次扣一次资源、生成一件 UID 物品；产物从生产器弹到空格。空格按固定近邻顺序选择，便于预测 |
| 满盘/体力不足 | 不扣费，不排队产生不可见物；在生产器附近短提示，指出可合成对、可交订单或恢复入口 |
| 点击普通物 | 稳定选中光圈，底栏显示名称、等级、来源/用途；信息按钮打开链路浮层 |
| 拖动 | 超过约 6–8px 再进入拖动；物品抬起 1.08–1.12 倍，产生落点轮廓；触摸时适当向上偏移避免手指挡住 |
| 放空格 | 移动同一 UID；成功落格，来源格空出 |
| 同物二合 | 校验同种同级及下一阶；两件输入归并为一件输出；当前彩椒→胡萝卜关系可作参考测试样例 |
| 不同物相碰 | 普通可移动食材默认交换；生产器、厨具、锁区遵循独立能力表，禁止“一律交换” |
| 投料 | 拖到兼容厨具后显示投入、缺料、产出与烹饪按钮；不能与普通二合混用判定 |
| 错误投料 | 原物回到原格，短提示可用原料，不吞材料、不触发假合成 |
| 取消/拖出/切后台 | 取消未提交的拖动，回到权威状态；切页前取消手势，不能留下幽灵物品 |
| 连续操作 | 成功动画不锁住整盘；正在提交的同一 UID 禁止重复使用，其他操作可安全入队 |
| 删除/出售 | 使用明确文案区分销毁与换金币；首版优先沿用可撤销出售，关键生产器与任务物禁止误删 |

烹饪状态机：`空闲 → 已投料 → 加工中 → 完成待取 → 空闲`。投料需要明确物品所有权：从棋盘转入厨具的 inputSlots，UID 不能仍被订单或仓库重复统计；点击开工才将保留材料消耗为唯一 job；未开工允许撤回，没空格时留在 inputSlots。刷新必须恢复投料。加工结束保留产物在厨具 outputSlot；满盘时继续等待，点击领取成功后才清空。任务 ID 和命令 ID 防止重复领取。

默认订单按自由棋盘/仓库库存计数，已投料和加工中的材料不再可交付。普通交付无需额外确认弹窗；消费、奖励、顾客进度、补位一次提交。是否允许逐项交付本轮未验证，首段采用已存在的整单原子交付。

体力只消耗在已配置的生产动作，普通移动、二合、切页不扣体力。恢复上限、间隔和阶段补给配置化，并记录 `lastRecoveryAt`；本轮只能确认当前车每次 1 点。加速券、钻石若未实现完整获取/消耗闭环，首段不放虚假的可点击入口。

沿用可保存的随机种子，只有成功提交生成才推进随机序列；满盘或写入失败不能偷偷改变下一次产出。原作本轮体力曾为 101，不能自行假定硬上限为 100；自然回复上限与奖励溢出上限应分开设计，建设奖励不得被无提示截断。

**6. 动效、音效和手感的交付标准**

| 事件 | 建议表现 | 目标时长，待实机校准 |
| --- | --- | --- |
| 点击/选中 | 按压、轻回弹、选择圈与轻音 | 70–120ms；即时起效 |
| 产出 | 生产器压缩回弹、食物短弧线落格 | 180–260ms |
| 移动/错误回退 | 贴近落点吸附/柔和回原格 | 100–180ms |
| 二合 | 两物收拢、短高光、新物回弹、少量粒子与音阶 | 220–320ms；不中断其他合法操作 |
| 烹饪 | 按厨具播放切菜/蒸汽/气泡，倒计时稳定更新 | 循环表现低频，不让整盘重绘 |
| 完成 | 成品轻浮动、一次提示音、明确领取状态 | 提示一次，持续可辨认 |
| 交单 | 菜品飞向顾客、顾客满足、金币飞到顶栏、下一客补位 | 450–650ms |
| 建设 | 箱子/围挡消失，物件落位、少量尘粒、阶段数更新 | 700–1000ms，可快速收束 |
| 切页 | 短过渡，左下按钮保持空间记忆 | 180–250ms |

区分点击、生产、合成、开工、完成、交单、建设七类声音；不要所有成功动作共用一声提示。触感仅在支持设备且用户开启时启用。提供静音与减少动态效果；减少动画时仍保留状态反馈。高频连点要限流音频和粒子，不能排成几秒播放不完的队列。

**7. 美术制作：先做一屏完整样板，再批量扩展**

目标为明快、饱满、短阴影的二维卡通，食物具有清楚外轮廓，界面材质服务于可点击性。现有低饱和写实街景与细碎食物图集不适合直接套用到参考构图。

美术样板先包含：一个生产器、砧板全状态、六件不同大小食物、两个顾客、订单卡、棋盘边框、纸箱、资源条、左下按钮和一处建设场景。将它们放在 390px 宽的真实游戏尺寸里一起审图，再扩张数量。

统一规范：左上主光；暖色描边；以 48px 展示尺寸计主轮廓约 2px；食物视觉占格宽约 70%–82%；统一落点、重心、投影方向和轮廓清晰度。细长食物按光学重量校正，不按图片边界框盲目缩放。低级与高级要通过形状、配料、器皿区分，不能只改颜色。

| 首段资产包 | 建议预算 | 验收方式 |
| --- | --- | --- |
| 食材与成品 | 2 条主链约 12–16 件食材、4–6 道独立成品 | 每件单独命名/ID，40–50px 下仍清晰；不复用成品图冒充多道菜 |
| 生产器与厨具 | 2 个生产器、2 种厨具；空闲/选中/工作/完成等状态 | 轮廓直接体现用途，动效不覆盖关键食物 |
| 顾客 | 4 位、各至少等待/期待/满足 3 表情 | 表情与订单状态联动，头像不挤占棋盘 |
| 棋盘与 UI | 格底、边框、选中圈、目标圈、锁区、按钮、订单、资源、提示 | 同一描边、圆角、阴影和字体规范 |
| 建设场景 | 1 间果蔬店，至少 3 个可见建设节点 | 每次建设能看出具体改变，不仅进度数字增加 |
| FX 与音效 | 产出、二合、厨具完成、交单、金币、建设 | 能区分事件，连续播放不刺眼、不拥挤 |

素材逐件校对后再打包图集；使用 manifest 记录 `assetId/frame/pivot/scale/source`，不继续依赖“整张 AI 图片自然形成准确 8×8 格子”。文字、数字、价格、倒计时由代码渲染。游戏画面不得出现 emoji 占位、模糊生成文字或明显不同画风素材。

**8. 第二页：建设必须成为玩合成的明确回报**

首段采用本次看到的等距果蔬店场景：箱子、柜台、货架与墙面构成空间，避免先扩展一整条宽幅街道。保留当前阶段一个主建设热点；点击打开建设卡，包含名称、当前步骤、费用、奖励、阶段奖励进度及一键建造。

金币不足时直接显示“还差 X”，提供关闭卡片回合成的清楚路径。能建时突出绿色按钮，结算与场景改变绑定。建设按节点推进（例如清理纸箱→搭货架→整理柜台），不把整店统一换个颜色作为升级。角色在手机上同样出现，可做少量待机/走动/满意反应。

闭环验收：完成订单→看见金币增长→回建设页→完成一个节点→领取实际奖励→回合成页继续。第一段应让玩家较早看到一次建设回报；具体价格由订单收入模拟校准，不能硬抄本次第 6 天的 82 金币当新手价格。

**9. 新手、内容和数值范围**

原作本轮已处于第 6 天，不声称知道它的完整开场。我们的首段目标是 15–20 分钟连续可玩、完成一次建设并见到下一目标。建议内容收敛为一店、两条食物链、两类厨具、4–6 道料理、10–12 个精心编排的订单。现有六章资源保留，先不追加内容预算。

教学建议：产出→二合→首单→投料→开工→继续合成等待→领取料理→交单→切页建设→自由操作。每一步有开始条件、目标 UID、完成事件、短文案和中断恢复；已提前完成的条件自动跳过。手势跟随对象，不写死屏幕坐标；用户移动目标、切页、刷新后仍准确。单次说明控制约 12–24 字。

首 30 秒目标完成一次合成，约 90 秒内完成首单，约 3–5 分钟内看到第一处建设变化。这些是设计目标，必须用首次玩家验证。早期不让所有生产器同时不可用；体力不足应有确定的恢复/阶段奖励路径。订单只引用已经可获得的物品与厨具，且连续数单分散消耗副产物，避免随机产出堆满棋盘。

数值表至少包含：生产消耗/掉落权重、每阶基础原料成本、加工输入与时间、订单需求与奖励、建设费用与奖励、体力恢复与解锁条件。固定随机种子模拟完成第一处建设所需点击数、体力、金币、峰值占格、等待时长；同时记录真人操作路径。三个产出样本不用于拟合概率。

领域状态需区分 `item / generator / appliance / blocker`，以 `canMove/canMerge/canAccept/canSell` 等规则判断能力。投料、计时、领取、订单均引用 UID/实体 ID，避免同一食材被并发消费。按事件驱动动画，动画完成与否不能决定结算是否成功。

命令队列不能简单保存旧的 from/to 索引：拖拽命令携带预期物品 UID 和目标版本，在执行时重新核验。上一个操作失败后，不得把下一次拖动作用到新占据该格的物品。反馈可以立即抬起/按压，最终资产变更仍以成功保存为准；失败明确回退并提示，不静默吞点击。

当前档案是 schema 1，固定 56 格、最多 6 天、8 格仓库，内容版本强校验。新网格、盘内设备和食物链必须升级 schema/content。迁移保留原始快照，逐 UID 映射旧棋盘/仓库/加工任务/进度；放不下的物品进入迁移待领取队列，不能截断删除。旧进行中料理保留原产物与结束时间。旧已完成订单奖励不得再次发放。

食物链重制不应按显示名称强行互换旧 ItemId。保留旧定义及贴图映射以兼容存量，新增参考链使用新 ID；首段新档与旧档各有测试夹具。迁移成功前不覆盖旧档；失败提供恢复和导出。旧教程数字节点映射到新语义节点，已完成的成熟存档不强制重走全部教学。

旧六章、六店、装饰、声望与新建设节点没有已确认的一一映射：保留旧进度记录，不猜测把声望换成厨师帽，不缩水旧金币。原作场景中的 26%、建设 0/3 与奖励 1/6 各自含义尚未全部确认，应建立独立字段与明确分母，不能全部绑定同一个进度值。
