# 鹅巷食光：已实现规则

版本：1.0.0 · 2026-10-23（北京时间）

本文件说明当前可运行代码。内容定义位于 `src/content/catalog.ts`，唯一资产结算入口是 `src/domain/engine.ts` 的 `execute(state, command, now?)`。Phaser 和 React 只发命令、显示结果。`recipe.duration`、任务结束时间与生成器恢复时间均使用毫秒。

## 内容与章节

首版包含 6 章、84 张固定主线订单（每章 14 张）、6 家店（各 3 次升级）、8 条七阶合成链、24 道确定配方、12 位顾客与 24 件装饰。56 种食材和 24 道料理合计 80 个图鉴条目。四位最早登场的熟客拥有随章节推进的四段对话，其余顾客也有四段短故事。

## 棋盘、生产与库存

- 棋盘固定 7 列、8 行；未开放的格子不能放物品。同种非最高阶食材二合后成为下一阶，两份输入均消耗，产物获得新唯一编号。不同物品、最高阶物品和料理交换位置；空格允许直接移动。
- 第 n 阶食材的基础材料价值为 `2^(n−1)`。八条链独立生产，固定产出本链一级食材，因此任何主线材料都具有确定来源，不依赖稀有概率。
- 每条生产链持有 12 份配额；用尽后等待 8 秒恢复全部 12 份。生成免费，没有体力费用。满盘时拒绝生成，不消耗配额、不启动冷却。
- 仓库容量为 8。入仓和取出保留物品唯一编号。交单及烹饪统计棋盘与仓库的总库存，按精确物品编号扣除；高阶物品不会自动替代低阶物品。
- 所有食材和料理都可出售。食材售价等于基础材料价值；料理售价不超过其输入材料售价之和，因此烹饪不能制造倒卖利润。生成器和厨具属于独立系统，不在可出售物品中。
- 出售后可撤销一次，返还原实例并扣回同额金币。任一后续成功命令都会终止撤销资格；失败命令不改变资格。撤销还会检查版本号、原位是否空、余额及重复编号。

## 烹饪

四个独立加工槽分别对应小鹅煎炉、手冲吧台、竹笼蒸锅和炭火烤架；前两个在第 1 章开放，蒸锅在第 3 章开放，烤架在第 4 章开放。每个配方规定一个厨具，不能占用其他厨具槽。

开工前一次校验全部材料和槽位，成功后一次扣除全部输入，生成独立任务编号并保存开始/结束时间。配方基础耗时 4–40 秒。装饰的效率加成只在开工时确定，后续升级不会重建或清空任务。

到时后主动领取。优先进入棋盘；棋盘满时进入尚有空间的仓库；两处皆满时保留任务和料理，不重复结算。领取后任务槽清空，因此连续点击不能重复发放。

## 订单、金币与建设

每章最多展示三张未完成订单；交付一张后，后续订单补位。只有当前展示的订单允许提交。每单包含 1–3 项需求，全部满足后原子扣除、发放金币与声望、记录完成编号。缺少一项时不扣其他材料，已完成订单不能再次领奖。

订单基础奖励为 `36 + 经营章×14 + 材料基础价值×8` 金币。料理的基础价值按其全部输入递归求和。声望为 `5 + 经营章×2 + ceil(材料基础价值/8)`；目前作为经营累计成果展示，不再增加额外的章节门槛。

每店按“整理 → 开张 → 焕新”升级三次，金币价格固定。装饰必须等所属店铺开张后购买，各限一次。每件小费装饰增加 2% 订单金币，全街合计最高 20%；每件效率装饰缩短 3% 加工耗时，合计最高 30%。加成按加法累计，金币向下取整，加工时长向最近毫秒取整。

完成当章 14 单并将该章店铺升级到“开张”后，玩家主动进入下一章；现实日期不会改变经营章。第 6 章完成后可继续整理、合成、收集图鉴和装饰，不重置已完成订单。

## 状态与时间边界

成功命令在独立状态副本上提交，`revision` 增加 1，返回事件；拒绝命令返回原状态引用和中文原因。界面动画不修改库存。物品与加工任务共享递增编号空间，避免编号重复。

有效时钟采用已保存时间的安全下限，系统时间倒退不会让任务或冷却提前完成。每次前向时间增量最多 24 小时；由于最长加工仅 40 秒，正常离线恢复可完成已开工料理并恢复配额。离线不产金币、不自动开工、不自动交单。超出安全整数范围的存档时间会拒绝提交，需通过存档恢复功能处理。

合法状态始终存在恢复路径：满盘可出售或合成，满仓可取出或直接交单/烹饪；金币用尽仍可免费生成并出售材料。主线不消耗不可再生钥匙，所有新章节依赖只指向已开放内容。修改存档形成的任意损坏状态，由持久化层校验和备份恢复负责处理。

## 主要领域 API

| API | 用途 |
| --- | --- |
| `createInitialState(now?)` | 创建符合 schema 1 / content 1.0.0 的新档 |
| `execute(state, command, now?)` | 唯一命令提交入口，返回 `{state, ok, events}` |
| `inventoryCount(state, item)` | 棋盘和仓库中的精确数量 |
| `canAffordRequirements(state, needs)` | 合并重复需求行后检查总库存 |
| `availableOrders(state)` | 当前最多三张可提交订单 |
| `getDayProgress(state)` | `{completed,total,ratio,shopReady,canAdvance}` |
| `unlockedCells(state)` | 当前开放格数：42、49 或 56 |
| `getGeneratorStatus(state, chain, now?)` | `{remaining,readyAt,waiting,unlocked}`，`waiting` 为毫秒 |
| `mergeTarget(item)` | 下一阶编号；最高阶或料理返回 `null` |
| `canCook(state, recipe, slot?)` | 检查解锁、指定槽位、空闲与材料 |
| `getBonuses(state)` | 小费和效率的有界累计加成 |
| `getOrderReward(state, order)` | 含已生效小费的实际金币奖励，界面与结算共用 |
| `getRecipeDuration(state, recipe)` | 含效率加成的实际毫秒耗时，界面与开工共用 |
| `stateInvariantErrors(state)` | 诊断资产编号、容量、配额和内容引用等不变量 |

命令与事件的具体 TypeScript 契约见 `src/domain/types.ts`。存档校验比诊断不变量函数更严格；导入数据必须经过持久化校验入口。
