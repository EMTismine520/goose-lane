# 离线运行与版本更新

生产构建执行 `npm run build`，Vite 完成后运行 `scripts/build-sw.mjs`。脚本依据 Vite manifest 遍历正式 `index.html` 的静态、动态依赖，生成游戏核心清单；预览、诊断、导出与未引用的旧素材不进入核心预缓存。静态文件仍按路径和 SHA-256 生成版本化 `sw.js`；Source Map、构建预算报告与 worker 自身不进入缓存。核心预缓存超过5 MiB或完整资源清单超过16 MiB时构建失败。`offline-budget.json` 列出本版实际核心文件和大小。

主题图片使用单独的版本化缓存，依据原图与移动图 manifest 的主题编号分包。游戏可玩且空闲2秒后按当前主题准备128像素移动图；设置内可选择下载全部主题的移动图和256像素详情原图。旧档按实际旧内容补齐兼容素材。`CACHE_THEMES` 只接受1至8的主题编号，`variant: mobile/full` 区分自动与完整下载；旧页面不带 variant 的消息仍兼容。实际缓存完成后才返回成功状态，下载中断可重试。

主题任务按资源合并，后台最多1个请求。`CACHE_PAUSE` 与 `CACHE_RESUME` 配合页面的点击、拖动、滚动、前后台状态和图片队列空闲信号，操作时停止发起新的补缓存请求，空闲后继续。已经进行中的单个请求允许完成。前台同资源请求共享下载，不等待整个主题包；CacheStorage 不可用时仍可联网游玩。

`src/platform/pwa.ts` 的 `registerPwa(onUpdate, onError?)` 只在生产构建注册。开发服务器不会注册 worker，以免开发代码被缓存。部署需要 HTTPS（本机 localhost 是浏览器允许的例外），静态服务要正确提供 `sw.js` JavaScript MIME 类型。项目使用相对 base，注册、manifest 与缓存范围会跟随实际安装子目录。

## 接入

页面入口加入 `./manifest.webmanifest` 的 manifest link，以及 `./app-icon-180.png` 的 apple-touch-icon link。棋盘或街景可玩且空闲2秒后才调用 `registerPwa`，卸载时调用清理函数。独立预览与性能入口默认不注册 worker；性能入口显式 `offline=1` 时才启用，离线重开仍使用正式 `index.html` 测试。

`onUpdate` 收到一个 `activate: () => Promise<void>` 函数。此时仅显示“新版本可用”；用户确认并且当前没有进行中的游戏命令、存档已经完成后，才调用 `activate()`。函数向 waiting worker 发送 `SKIP_WAITING`，收到 `controllerchange` 后刷新当前页面。函数会报告超时错误；UI 应保留重试入口。初次安装不会自动刷新页面。其他已打开的标签页不会因本标签页点击更新而被应用代码强制刷新。

## 一致性与失败处理

- 安装逐个准备核心文件；优先复用 HTTP 缓存或经新版本 SHA-256 验证相同的旧缓存内容。请求附完整性校验，失败时以 reload 策略重试一次。核心未完整准备好就不安装成功；失败仅删除本次核心缓存，旧 worker 与旧缓存继续工作。
- 新 worker 不自行 `skipWaiting`。用户未确认时，当前页面与离线资源保持旧版；所有页面都关闭后，由浏览器按标准生命周期自然激活新 worker。
- 正式游戏导航立即返回已安装版本的 `index.html`，无需等待网络探测。缓存缺失时尝试健康的网络响应，网络不可用则返回恢复页；不把新 HTML 写入旧版缓存。独立诊断和预览导航不替换成游戏首页。
- 静态资源优先读取当前版本的精确 URL 缓存；丢失的条目只能以相同 SHA-256 内容修复。不会把新的同名图片写入旧版缓存。
- 构建清单内的静态资源按精确URL和内容哈希识别，缓存匹配忽略服务器的Vary头，避免 `Vary: Origin` 令预缓存模块在离线CORS加载时失配。该规则不扩展到API、外源或未知资源。
- 仅处理同源 GET 和构建清单中的静态资源；外源、非 GET 与未知 API 请求不进入离线缓存。
- 激活后保留当前与上一版核心及主题缓存，只清理同一 scope 更早的缓存。旧页面延迟请求带 hash 的 JS/CSS 时可读取上一版缓存；部署同样保留上一版带 hash 文件，以兼容尚未刷新的标签页。
- 恢复联网或回前台后，等玩家空闲再检查 worker 更新。离线检查失败不影响游戏。

## 旧版白屏恢复

旧版 worker 会拦截范围内所有页面；如果旧 `index.html` 缓存缺失，新页面的内容校验也不匹配，就会只显示“离线资源未完整保留”。这时网页代码没有加载，游戏内更新按钮无法出现。

[B 组直达入口](https://emtismine520.github.io/goose-lane-art-preview/recover.html) 放在独立的 `/goose-lane-art-preview/` 路径，位于旧 `/goose-lane/` worker 范围之外，因此已经卡住的设备也能打开。旧恢复链接现在立即跳转到 B 组暖色卡通试玩，不需要点击按钮，不读取旧存档，也不调用旧 worker 的注销流程。试玩使用独立测试盘面，不注册离线程序。正式游戏的存档与离线流程保持原有行为。

新版遇到缓存缺失且网络不可用时返回带手机 viewport、重试按钮和独立恢复链接的 HTML，而不是无法操作的小字页面。

## 验证边界

`tests/pwa.test.ts` 自动验证构建确定性/体积限制、完整缓存安装、失败不伤旧版、离线导航和资源、HTML 版本隔离、scope 清理、请求边界，以及手动激活和刷新时机。这些测试在 Node 的隔离 worker 模拟环境执行；它们不等于真实浏览器离线验收。

3.0.0另已在真实桌面浏览器下载全部主题后停止生产预览服务器，验证离线重启、棋盘加载和首次查看后期主题图片成功。证据位于 `docs/validation/v3/offline-check.json` 与对应截图。实体手机安装和首次玩家验收仍待完成。

真实浏览器验收应使用生产预览或 HTTPS 部署：完整联网打开一次，确认 worker activated 和缓存完整；切换离线后重新打开游戏；恢复联网部署新版，确认只出现更新提示；保存完毕点击更新，确认新版本加载且存档保留。还应分别检查 Android 安装、iOS 添加到主屏幕与子目录部署。

离线能力需要至少一次完整联网加载。浏览器仍可能因存储空间不足、无痕模式或用户清理站点数据而移除缓存。缓存保存的是应用资源，游戏存档由现有 IndexedDB/备份机制负责；PWA 不替代导出存档。

图标从项目原有鹅图形规范化，SVG 与 180/192/512 PNG 均保存在 `public`；不依赖外部图标服务。
