# 移动端性能实现与复现

本次按 `plan2` 实施，继续使用现有免费 GitHub Pages，不需要域名、付费 CDN 或新增服务。保留两个主页面、B类画风、经济规则、配方、IndexedDB与三个手动存档槽位。

## 进入游戏

- HTML 先显示轻量启动画面，存档读取与 Phaser 模块准备并行。
- `src/game/board-assets.ts` 根据当前棋盘规划资源：当前物品、设备为必需；生产器产出、下一阶合成与料理结果优先预热。图鉴历史、已解锁主题不会扩大阻塞集合。
- `src/platform/asset-queue.ts` 供 React 与 Phaser 共用，前台并发4、同URL请求合并、优先级提升、原生图片解码后交付。解码引用采用96项／12 MiB上限；已有棋盘纹理由 Phaser 持有。
- 311张256像素原图全部保留，新增128×128透明无损WebP。内容哈希写入文件名，避免更新后同名缓存污染。界面图标按显示像素选图，详情保留原图；原图离线不可用时可回退移动图。
- 新档阻塞7种纹理，第八主题样板31种；烹饪结果和新图按需替换对应对象，不重建整盘。失败时可局部重试，旧会话完成的加载不会覆盖新存档。
- 街景、图鉴、详情和设备面板按打开需要加载，首次访问后复用。

## 绘制与提交

棋盘默认DPR上限2、60fps目标和上限；Safari继续自动选择渲染后端，微信继续Canvas。预览的显式覆盖仍支持3倍采样。逻辑格子和所有63格指针坐标保持不变。

拖动位置每帧最多更新一次，按压时与视口变化时测量缩放；同一落点不反复重画高亮。设备文字和进度按变化更新。切页或后台暂停场景与循环，返回恢复尺寸和状态。持续掉帧时先减少蒸汽、装饰粒子，保留操作反馈与用户的低动态设置。

根组件不再每500ms重绘；需要倒计时的局部组件按秒更新，恢复任务按实际完成时间唤醒。命令继续串行、原子落盘后发布成功；释放拖动后保留落定中的反馈。优化只跳过队列空闲时完全相同的选中和订单滚动状态，页面命令、占用校验、失败恢复与更新前排空保持有效。

## 缓存与更新

首次注册延后到可玩并空闲2秒后。核心按正式游戏依赖图生成，当前约32项／2.33 MiB原始字节；旧版137项／4.45 MiB。已安装版本的导航直接读缓存。主题图片在空闲时逐项补齐，后台并发1，操作或隐藏时暂停新增请求；完整主题下载保留设置入口。

同内容跨版本复用前校验哈希，当前与上一版资源并存。玩家点击更新后先保存和排空队列，再激活等待中的版本。详见 [PWA协议与失败处理](PWA.md)。

## 本地性能入口

生产构建后可用普通静态预览，或使用仓库自带、仅监听本机的限速服务器：

```powershell
node scripts/serve-performance.mjs --port 5212 --rate 10000000 --latency 100
```

打开 `http://127.0.0.1:5212/r/run-01/performance.html?perf=1&lab=1&scenario=late&run=run-01&renderer=canvas`。

- `scenario` 支持 `opening/orders/theme-unlock/prefix/loaded/cooking/ready/full/build/street/late/complete/legacy`。
- `run` 为隔离存档名；`/r/<新名字>/` 同时提供新的HTTP缓存命名空间，不清理玩家数据。
- `renderer=canvas` 用于Canvas检查，省略时自动选择。诊断页面默认不注册离线程序。
- “性能记录”可以生成、导出JSON。记录导航分段、存档恢复、引擎及棋盘就绪、图片加载和解码、按压／拖动首帧、命令执行／持久化／发布、帧分布；没有远程上报。
- `lab=1` 仅由本机测量服务器插入轻量观察器，等待棋盘ready与随后两个绘制帧后记录耗时、资源响应体。服务端限速不包含DNS/TLS，不模拟手机CPU、触摸硬件或真实微信网络。

正式游戏也可显式 `?perf=1` 打开本地性能记录，直接测量当前存档；加 `&renderer=canvas` 可在诊断会话中固定Canvas，未开启perf时该参数不改变正式渲染策略。请勿通过清理微信站点数据制造冷启动，这会删除本机存档。

## 真机验收

桌面浏览器和限速采样不能代替iPhone／微信验收。仍需iPhone 11或SE二代档与较新iPhone，各用Safari及微信完成：新档／第八主题冷启动、缓存重开、弱网和离线各10次；完整产出到建设流程；满盘、多设备、图鉴长列表；20次切页、20次后台恢复及30分钟持续游玩。

记录系统、微信／浏览器版本、后端、网络、电量与低电量模式，保存诊断JSON和录像。目标：10Mbps／100ms冷启动P75≤3秒、P95≤5秒，4Mbps／200ms的P95≤8秒；缓存重开P95≤1.5秒；反馈P95≤50ms、正常存储提交P95≤120ms；60Hz真机平均≥57fps、帧间隔P95≤20ms、>50ms帧<1%。未实测的目标保持待验。

正式链接的存档继续保存在原GitHub Pages域名与路径；独立诊断存档不能替代正式存档升级验收。
