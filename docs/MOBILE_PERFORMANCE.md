# 微信移动端渐进加载

当前实现采用“当前厨房先可玩、随后全部缺失游戏资源立即下载”的方式。正常游戏继续使用 GitHub Pages、React 和 Phaser；不新增旧档迁移。本次加载改造不改变玩法规则、存档schema或保存成功后发布状态的顺序。

## 首次进入

HTML提供独立于主脚本的轻量启动画面。当前存档就绪后，按恢复页面准备所需模块；街景不提前启动Phaser。棋盘的关键图片与引擎并行下载，场景无需等待所有图片解码。暂缺图片以物品或设备名称显示，保持可识别和可操作；图片逐张替换，不重建整盘。`board-ready`表示基础交互可用，`board-assets-ready`单独记录当前图片齐备。

`board-assets.ts`只规划当前可见所有权，图鉴和历史解锁不会扩大首屏集合。下一次生产、合成和料理结果在首帧后预热。图片失败可局部重试，网络恢复时重试当前缺图。

章节购买先准备全章实际上盘器材的目标等级运行图及首屏订单图，完成后才扣币、保存并进入；再次进入按已保存的真实棋盘准备。海港章18台器材的128像素运行图合计158,608字节，棋盘初始19个纹理含一张锁区图；订单图和应用代码另计。其他阶食材与高清详情仍在后台准备。

## 图片和内存

323项已选512像素原图保持原字节。从完整透明画布生成128及256像素无损WebP，不裁边、不改主体比例。显示CSS尺寸乘实际像素比后选择合格档位，超过256像素使用512原图；棋盘正常像素比上限2，显式诊断仍可使用3。

`mobile-art.json`和`medium-art.json`提供路径映射。不同尺寸使用带内容哈希的URL；不再为512原图复制一份同字节的移动地址。后台下载只缓存响应字节，不批量创建Image或Phaser纹理。

React和Phaser使用同一个4并发图片队列。请求可提升优先级，同URL共享；关闭弹层和切章时释放消费者，最后一个消费者离开才取消任务。解码LRU继续限制96项或12MiB。场景按当前工作集、可见对象、拖动和动画的实际引用回收纹理，保留使用中的资源。

Phaser使用安装版本随包提供的官方Arcade Physics精简构建，排除本游戏未使用的Matter.js，保留Canvas和WebGL。没有重写棋盘引擎。微信仍默认Canvas。

## 后台自动准备

首次可玩后立即注册Service Worker，不等待输入空闲。全部缺失的章节运行图、功能代码与512原图同轮提交，由浏览器管理连接。没有应用层下载并发或速度上限，也没有高清阶段屏障。下载进度通过独立Context和UI帧合并更新，不驱动游戏根组件和棋盘重绘。

拖动、命令保存、前台图片、saveData、网络类型和页面隐藏都不触发程序自动暂停。前后台同URL共享读取、校验和缓存提交，首访接管按正在加载的具体URL交接。设置按钮的小标记展示真实已缓存进度，设置页提供接收速度、补试状态及玩家主动暂停/继续。

目标意图独立保存在版本化资源元数据缓存。worker重启或页面重开后重新核对真实缓存，只补缺少文件。文件级续传；程序不主动在隐藏时停下载，微信或操作系统仍可能挂起执行，恢复后重新核对并补缺。离线和缓存容量失败不阻止已具备资源的玩法或联网按需加载。

## 预算与复现

运行 `npm test` 和 `npm run build`。构建检查全部派生图与来源一致性，生成 `dist/performance-budget.json` 和 `dist/offline-budget.json`。首屏预算现在同时包含代码gzip参考与可见图片，不能只检查代码却宣称总量达标。已选全量美术没有固定总量或128像素的硬限制。

使用 `node scripts/serve-performance.mjs --port 5212 --rate 10000000 --latency 100` 提供本机生产预览。`performance.html?perf=1&scenario=late&run=独立名称&renderer=canvas` 使用隔离存档；`/r/独立名称/`可提供独立HTTP缓存路径。诊断默认不注册离线程序，显式 `offline=1` 才启用。

记录导航、模块、读档、引擎、可玩首帧、worker注册和接管、全量派发、当前图像、交互和资源包齐备标记。显式perf=1的导出另含worker内的正文、校验、写入、补试和缓存复用指标；协议与实际传输不可观测时用null，不推测为0。构建gzip参考不等于真实HTTP传输；桌面模拟不等于微信真机。不要清除玩家站点数据制造冷启动。

## 真机验收

需要实际Android微信、iPhone微信和Safari，覆盖新档、后期、多厨房、冷启动、缓存重开、弱网、离线、全量下载期间操作、章节切换和后台返回。参考目标为10Mbps/100ms冷启动P75≤3秒、P95≤5秒，4Mbps/200ms后期P95≤8秒，完整缓存重开P95≤1.5秒。采集至少20次核心场景样本，并记录设备、系统、微信版本、网络和渲染后端。

30分钟持续游玩和真实触摸反馈需要独立真机结论。2026年10月28日的旧版桌面数据属于历史版本，不用于证明当前微信速度。

## 全量下载效率

以同版缺失URL集合、同设备浏览器和等价缓存状态比较原生全部fetch的T_native与游戏实际校验写缓存的T_full。10Mbps/100ms和4Mbps/200ms分别20轮配对采样，目标T_full P95不超过T_native P95×1.20＋2秒。测试服务器整形只用于实验，不进入生产下载器。全部资源SHA-256及离线读取核验通过才代表准备完成；节点网络和真机结果单独记录。
