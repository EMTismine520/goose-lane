# 双页版本行为、数值与兼容契约

下方经营数值与兼容章节保留 schema 2、content 2.0.0 的历史版本边界；当前内容版本 3.0.0 的棋盘输入采用本节规则。原作实玩事实来自 `../../docs/TWO_PAGE_REPLICA_PLAN.md`；以下未实测部分均为本项目的明确设计决定，不声称是原作隐藏规则。既有 schema 1 定义及六章进度保留。

## 当前棋盘点击与拖动（2026-10-25）

- 点击食材或成品只选中查看，再点同一件取消。点击生产器直接产出；点击厨具按其状态查看材料/进度、开火或领取，之前的选中对象不改变点击含义。
- 移动、交换、合成和投料只能通过有效拖动提交。设备的移动和合成继续服从 `canMove`、`canMerge` 等领域约束；拖到设备不补发产出、开火或领取。
- 位移按从起点量出的最大 CSS 距离判定，达到 7 CSS 像素即消费拖动手势；拖回原格、拖出、跨格轻移或中途取消都不补发点击。DPR 不改变阈值。
- 点开放空格、锁区或明确标记的棋盘背景/边框，统一清除选中与临时“找一对”提示。顾客卡、按钮、弹窗及其关闭遮罩处理自身操作。普通选中只高亮当前对象，可合成目标仅在拖动、“找一对”或教学时提示。
- 明确取消、切页、弹窗接管、恢复现场及失焦/后台取消会使旧的拖动回选失效；已提交的合法资产命令继续保存。成功合成等待新快照后选中新 UID，后一次选中意图优先。
- 方向键移动键盘焦点，Enter/Space 使用相同点击规则，Escape 取消选中。没有两次点击搬运或投料入口。

## 页面与首段边界

- 持久主页面只有合成与美食街；图鉴、仓库、设置、建设卡和旧日内容是弹层。
- 新档首段为两条新链、六道料理、十二份顾客订单、一间果蔬店与三个建设节点。
- 十二单全部完成且小店建设完毕后，显示首店完成，玩家仍可生产、合成、烹饪、收集和整理库存。不会自动跳到尚未完成新版制作的第二天，也不会重复发放已完成订单奖励。`nextDay` 对 fresh 存档明确拒绝。
- legacy 存档保留原日数、六店、装饰、声望与旧订单语义；日数推进仍由旧订单及旧店铺条件决定。新厨师帽不与声望互换。

## 棋盘、设备与所有权

画布是 7 列 × 9 行，索引按行优先 0–62。设备索引为 35 蔬菜推车、36 鲜果木箱、40 小鹅砧板、41 鲜果料理台。食物保存在 `board`，设备来自 `BOARD_LAYOUT`；设备所在格不能同时存食物，不能移动、交换、出售或进入仓库。

下部三个一行宽的纸箱区由配置描述 footprint，不假设原作内部一定采用同样数据结构：

| 索引 | 新档解锁条件 | 旧档解锁条件 |
| --- | --- | --- |
| 42–48 | 清理门前纸箱完成 | 第 3 天 |
| 49–55 | 搭建蔬菜货架完成 | 第 4 天 |
| 56–62 | 整理迎客柜台完成 | 第 5 天 |

解锁条件与标签均来自 `getBoardEntity`；不能使用新档永远无法达到的后续日数装饰锁区。建设成功后对应一行直接可用，不需要另付一笔解锁费。

- 普通食物与空格相碰：移动同一个 UID。
- 同种同级且有下一阶：两件输入归并为一个新的输出 UID，材料基础单位守恒。
- 不同普通食物、或已到最高阶的同类食物：交换位置。
- 设备或锁区：按能力判定；不能一律交换。
- 生成空位按生产器所在格的曼哈顿距离排序，同距按索引排序。
- 订单与旧配方消费只统计自由棋盘和仓库，不统计投料、在制品、设备成品与迁移待领取箱。

## 体力与生产

本轮原作只能确认一次推车产出扣 1 体力。这里的回复、上限、权重均为项目调校值。

| 参数 | 配置 |
| --- | --- |
| 新档体力 | 60 |
| 每次成功生产 | 1 体力 |
| 自然回复 | 每 120 秒 +1 |
| 自然回复上限 | 100 |
| 建设奖励溢出 | 不截断，可以超过 100；达到上限后不继续自然回复 |
| 两条新链掉落 | 1 级 72%、2 级 20%、3 级 8% |
| 旧链生产 | 1 体力，确定产出该链 1 级食材 |

满盘、体力不足、锁定链或无效命令均不扣体力、不推进随机种子。成功才将食物、体力、种子与命令 ID 一起提交。普通移动、合成与切页不消耗体力。时钟回拨不增加资源，单次离线时间上限保持 24 小时。

旧 schema 1 的 12 次配额 / 8 秒回复仅保留在历史回归夹具，不是新版玩家界面中的生产规则。

## 投料与烹饪状态机

`空闲 → 已投料 → 加工中 → 完成待取 → 空闲`

1. 投料立即把同一 UID 从棋盘移入该厨具的 `inputSlots`。必须是至少一个可用配方的合法子集；错料或多余配料整次拒绝，原物不变。
2. 未开工可逐件撤回同一 UID；没有空格时保持原投料状态。投料可刷新恢复。
3. 明确点击开工才消耗已保留材料并生成唯一 job。多原料必须恰好齐备；界面动画不参与资产结算。
4. 按时间戳判定完成。`recover` 或下一次成功操作使成品成为 `outputSlot` 中的独立 UID。完成不自动把成品放入棋盘。
5. 领取必须有棋盘空位，新厨具不会悄悄放进仓库。满盘继续保温，任务与产物都保留。
6. 领取校验 `expectedJobId`，成功后清空 job/outputSlot；重复领取不能再发一个成品。
7. 导入的旧任务留在旧 `jobs`，保留原产物与结束时间；其旧领取规则仍允许满盘时进入有空位的仓库，避免破坏既有约定。

六道新菜不接受旧式一键 `cook` 捷径，必须通过盘内投料与开工。

## 教学、输入与保存

教学语义顺序是产出、二合、首单、投料、开工、等待时继续操作、领取、料理交单、访问街区、建设。只有成功提交的游戏事件会推进；失败或取消不会推进。提前发生的成功事件保存为完成历史，进入对应节点时自动跳过。

合成目标存实际物品 UID，移动或刷新后仍可定位。开工与领取目标跟随实际使用的厨具，包括先选择水果料理台的路径。已提前领取料理会自动完成等待节点，不要求玩家再开工一次来“补教程”。完成的成熟旧档不会重走教程。

`session` 保存页面、选中 UID 与订单带位置。选中、切页、设置或被动时间恢复不会取消尚可撤回的出售；实质游戏操作使该撤销失效。

命令可带 commandId、预期来源 UID、目标 UID、目标 cellVersion、厨具版本或 jobId。执行时再次核验，不把排队中的旧索引动作套到后来占据此格的另一件物品。近期 256 个 commandId 保存去重；交单、建设和领取还分别由订单 ID、节点顺序、jobId 作业务层幂等保护。

迁移逐 UID 保存棋盘、仓库、投料、任务与待领取物。设备占格或锁区冲突时先找合法空位，再进入 `migrationInbox`，绝不截断丢弃。迁移待领取箱不直接计入订单库存。

## 已执行的节奏与正确性验证

`src/diagnostics/opening.ts` 使用固定种子、真实领域命令和真实合成/加工规则，不注入金币或库存。三个种子完成十二单、六菜、三个建设节点，生产 40–53 次，操作 112–136 次，峰值食物占格 7–9，等待约 119.5 秒。首次建设支出前收入为 28 金币，支付 24 后剩 4。

按脚本每次操作 2.5 秒，整个首段为约 6.7–7.7 分钟。按读提示、找目标、拖动和思考合计 **8 秒/操作的假设**，估计约 **17.0–20.1 分钟**。后者是推算，不是真人测试，不能标记为已完成 15–20 分钟首次玩家验证。首建在自动路径中约 32–34.5 秒，亦不能冒充真实玩家达到 3–5 分钟目标的证据。

领域测试覆盖旧六章四种策略、旧版 3000 次混合操作、新版 1800 次混合操作、UID 与物料守恒、误投、缺料、满盘撤回、三个加工时点的序列化恢复、双领取、重复交单/建设、体力溢出、锁区、20 次切页、提前完成教学与目标随 UID/厨具移动。浏览器、真机性能及首次玩家结果记录在独立验收报告中，不能用领域测试替代。
